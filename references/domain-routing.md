# 领域语义路由

由当前 Agent 阅读用户完整问题，先判断信息是否足以起卦，再选择一个领域。不要使用关键词计数，也不要让用户重复选择已经表达清楚的内容。

## 起卦前清晰度门槛

问题至少应让 Agent 能识别：

1. 用户正在询问的核心事项或关系；
2. 用户希望判断的主要结果。

两项都能从原问题理解时，直接分类，不为补齐结构化字段而追问。只是领域边界不唯一时使用 `general`。

若任一项无法识别，先不要起卦，也不要猜测。只提出一个能解除当前歧义的简短问题；得到回答后重新判断并继续。不得一次索要领域、子类型、期限、视角等整套字段。

一句话包含多项内容时，先区分是“多个独立事项”还是“同一事项的互斥选项”：

- **独立多事项**：判断目标不同，或时间范围不同。询问用户本次优先判断哪一个，不要一卦答两问。
- **互斥选项**：共享同一个判断目标和同一个时间范围，只是分成几条互相排斥的路径。这属于一件事，按[选项对比](#选项对比)处理，不要拆开，也不要要求用户先选一个再占。

判据是判断目标与时间范围是否一致，不是句子里出现了几个名词。

## 封闭枚举

- `career`：核心判断对象是职位、职业状态、组织环境、晋升、转职或事业推进。
- `wealth`：核心判断对象是资金取得、收益实现、回款、交易结果、经营现金流或财务得失。
- `relationship`：核心判断对象是恋爱、婚姻、伴侣互动、关系发展、去留或复合。
- `academic`：核心判断对象是学习过程、考试表现、成绩、录取或学术进展。
- `travel`：核心判断对象是行程能否成行、途中状态、目的地环境或行人归期。
- `home`：核心判断对象是住宅、居住环境、搬迁、房产取得处置或产权手续。
- `legal_risk`：核心判断对象是争议、诉讼、仲裁、程序压力、证据与风险升级。
- `relationship_family`：核心判断对象是亲属角色、家庭成员互动、代占亲人或家庭支持。
- `general`：问题语义不足、主目标无法唯一确定，或不适合以上专项方法。

## 裁决规则

1. 按用户真正要判断的结果选择，不按句中出现的名词选择。
2. 复合问题只选择决定最终回答结构的主目标；其他内容作为现实语境保留。
3. 问题事项和目标已经清楚、但无法可靠区分领域时选择 `general`，不要为获得分类标签而追问用户。
4. 路由只选择分析方法和初始关注点，不是盘面事实，不锁定最终用神、吉凶、应期或作用链。
5. 解读时若完整问题与盘面显示初始关注点不合适，允许说明理由后调整用神主线，但不得修改确定性卦盘字段。

## 示例

- “看看我最近怎么样”：信息不足，先问最想判断的具体事项。
- “我和他还能继续发展吗”：信息足够，路由为 `relationship`，不再询问领域。
- “这次面试能不能通过”：信息足够，路由为 `career`，不再追问职位类别。
- “工作能不能转正，另外这段感情会不会结婚”：判断目标不同，属于两个独立主问题，先请用户选择本次优先占问哪一个。
- “留在现公司还是去 B 公司”：判断目标同为去向、时间范围相同，属于同一事项的互斥选项，走选项对比，不要拆成两问。

## 选项对比

用户在同一事项下给出互斥选项时，路由照常选一个领域，另外向统一入口传 `--question-form option_comparison`，并声明选项与取用格式。

**爻位与选项的映射必须在起卦前声明。** 看到盘面之后再决定哪一爻代表哪个选项，等于事后挑一个符合预期的说法，映射将不可证伪。统一入口会把映射冻结进排盘结果，事实审计据此校验解读。

两种取用格式：

- `shi_ying`：恰好两个选项。其中一个是现状时由现状方落世；两个都是新动作时按声明顺序定序，先声明的落世、后声明的落应。两种定序都在起卦前确定，映射由脚本推导，不接受手工绑定。用神消歧照常进行。
- `yongshen_multi`：**恰好两个**选项，分别绑定到同一六亲的两次出现。此时用神多现取舍挂起，被绑定的每次出现按等位用神各读各的选项。

  绑定有两种写法。**序数**（`ordinal`）声明取用神的第几次出现，自下而上数六爻、再数伏神；它才是这个模式下可用的写法，因为**起卦前无从知道用神会落在哪一爻**，写死爻位等于无法真正在起卦前冻结。**具体爻位**（`ref`）仍然支持，用于爻值已知的复盘场景。两者不可混用。

  **一卦最多容纳两个选项。** 穷举 64 卦可知，任一六亲最多占据六爻中的两爻（含伏神亦然），所以三个及以上选项在这个模式下无解——不是实现限制，是纳甲结构使然。选项多于两个时应请用户两两比较。

  即使只有两个选项，也有约三分之二的卦里用神只出现一次。此时按序数绑定会被拒绝，应改用 `shi_ying`。

选择依据：**默认用 `shi_ying`**——它对任何卦都成立，不依赖用神出现几次。只有在确实想让两个选项落到同一六亲、做同类比较，且该卦的用神恰好两现时，才用 `yongshen_multi`。多于两个选项两种格式都不支持，请用户两两比较。

`travel` 领域的规则层用神本身就是世爻，与 `shi_ying` 语义重叠，统一入口会直接拒绝该组合；改用 `yongshen_multi` 或按单目标提问。

映射不完整、爻位不存在、两个选项绑定同一爻位时，统一入口拒绝排盘并报错，不会静默回落成单目标占问。此时补全参数重跑，不要改成自行推测。

## 性别与关系视角

- 不把性别设为通用必填项；确定性排盘不依赖性别。
- 事业、财富、学业、出行、住宅、纠纷等问题不询问性别。
- 家庭和代占询问实际亲属关系或代占关系，不用性别替代关系。
- 仅在异性恋爱或婚姻问题采用传统财官取用、且原文无法识别提问者视角时，询问男方、女方或“不按性别口径”。
- 同性关系、非二元身份或用户不愿提供时，不强制选择性别；使用 `unspecified`，依据双方角色、世应和完整语境分析。
- 预测胎儿性别不是路由或澄清场景，必须转入敏感分流并停止起卦。
